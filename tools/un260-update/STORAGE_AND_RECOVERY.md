# UN260 升级空间与恢复（2026-09-07）

## 本次已有板子的迁移

旧程序约 44 MiB，日志显示 rootfs 仅余 11,540 KiB；旧安装器要求 49,804 KiB。压缩包约 9 MiB 不等于解压及替换需要的空间。

本次混合资源版程序约 11.2 MiB，仍不能在当前空余空间里安全暂存并保留旧程序。建议备份设备配置及重要数据后，使用本次完整、匹配 Flash 几何的 IMG 迁移一次。对已确认 2 KiB 页/128 KiB 块的板子使用 `d211_d213_devkitf_page_2k_block_128k_v1.0.0.img`。完整烧录可能重置配置，不能当作无损升级。

不要先删除正在使用的程序，不要跳过空间检查，不要通过删除 U 盘缓存来期待根分区空间增加。本次没有修改 Flash 分区或烧录几何。

## 后续 UPK

继续放 `update/UN260_UPDATE.upk`。完整包携带核心文件，但设备逐文件比较 SHA-256 和权限：未变化文件不重写；树目录拆成文件计划；新增文件自动安装；目录内不在新包中的旧文件不隐式删除。

单独放 `update/test_lvgl` 仍兼容，可选 `liblvgl.so` 和 `lvgl_data/`，也使用空间检查与恢复事务。裸文件没有发布者签名，UPK 的 SHA-256 校验也不等于数字签名。

- 根分区预算：全部变化文件的未压缩大小（按 KiB 向上取整）+ 每文件 4 KiB + 2 MiB 安全余量。保守，不依赖 UBIFS 压缩碰巧节省空间。
- USB 需容纳解包内容及旧文件备份。备份写入后校验内容。
- 每次替换前，同一文件系统建立旧文件硬链接，写入校验过的新文件再 rename；全部完成前保留旧链接。
- `/var/lib/un260-updater/transaction` 保存本地恢复记录；启动脚本在启动 UI 前恢复未完成事务。回滚不必把几十 MiB 从 U 盘重新复制到根分区。
- 提交标记同步后才删除旧链接；中断后有提交标记则完成清理，没有则回滚。
- 失败且回滚成功会清理本次 `.un260_*` 工作文件；回滚未确认成功保留备份和记录。原 UPK 与 USB 根目录的日志、结果文件保留。
- 旧安装器留下且含有效条目的 `state.tsv` 不自动删除，需先核实恢复状态。仅预检失败且无事务条目的旧暂存可在下次处理时清理。
- 锁目录 `/tmp/un260-updater.lock` 防并发；意外强杀后同次开机可能留锁，应确认没有升级进程再处理，重启会清理 tmpfs。

日志：USB 根目录 `ui_update.log`、`UN260_UPDATE_RESULT.txt`。关注 `Install plan`、`Storage preflight`、`Rollback`。

## 构建保护与验证边界

打包器拒绝大于 16 MiB 的主程序或大于 24 MiB 的解压 payload。这是防回归预算，不是任何空间状态都可升级的保证；最终仍由设备可用空间预检决定。

运行 `sh tools/un260-update/test_updater.sh target/d211/d213_devkitf/rootfs_overlay/usr/bin/ui_update.sh` 和 `bash tools/un260-update/test_package_budget.sh`。测试均使用隔离临时目录。

主机模拟覆盖正常包、校验失败、非法链接、增量、空间不足、复制失败、恢复失败保留、提交前/后中断、路径穿越及裸文件兼容。它不是 A/B 分区升级；多个文件的切换并非全局原子操作，也不能替代真实 Flash 的断电测试。升级过程中不要继续操作其他 UI 功能、断电或拔盘。
