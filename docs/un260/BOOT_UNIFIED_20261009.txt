UN260 统一快速开机方案与验收
日期：2026-10-09
权威仓库：Linux /home/pc/d213-100ask/d211

方案与责任边界
1. initramfs 保留 PID1 早期入口、按内核参数挂载真实 root、切根能力；不内嵌品牌图片、动画逻辑、Welcome 字形或语言选择。
2. root 分区保存静态播放器、压缩主题包和清单。每个版本由内容与显示模式计算唯一 ID，文件不可就地覆盖。
3. 早期播放器在普通服务启动前读取本次语言和版本快照，播放完整品牌动画或静态 Logo。显示期间不逐帧读资源，不中途切换语言或版本。
4. 主 UI 同时准备配置、设备、协议和自检对象。只有早期播放器真实首帧确认后才启动并行初始化；拿到独占显示权限和真实 framebuffer FD 后才刷新屏幕。
5. 正常路径直接进入原有自检，不再重播另一段 LVGL 品牌动画。动画模式保留入口和 Welcome 自然落定所需的时间，移除额外长驻留；Logo 模式在 UI 准备好后即可交接。
6. 正常 SPL 启动资产使用 DT 原生 400×1280 的中性黑色，烧录维护画面保留。客户品牌画布仍为 Linux 横屏 1280×400，统一归 root 资源包。现有 SPL 面板 compatible 与已编译驱动不匹配，不能仅凭黑图证明 SPL 显示生效；本轮保留其硬件时序，早亮屏走已存在的 Linux 显示路径。
7. 保留原有 UART 确认、自检、触摸校准、故障引导、升级恢复与渲染机制；早亮屏不表示主控已完成自检或可以点钞。

更换客户动画或 Logo
唯一显示主题仍由 source/artinchip/test-lvgl/un260/lv_core/boot_anim/boot_theme_config.h 控制，当前主题 D。
root 资源生成器读取 un260/boot/boot_bundle_config.json 的 mode 与 logo_surface；动画和 Logo 都通过正常应用构建及完整 make 形成新版本。
具体配置键和相对路径要求以配置文件与生成器校验为准。静态 Logo 画布为 1280×400；不符合几何或解码预算的资源拒绝打包。
资源格式校验通过后，仍需通过完整 UPK 的 24 MiB 解包预算与安装存储预检；复杂图片可能超额，构建会明确拒绝，不能保证任何合格尺寸的 PNG 都可直接发布。
C/D 主题分别沿用当前 C/D 动画与十语言手写 Welcome，十种语言在构建端准备。新增任意动画类型需提供匹配播放器和资源包，但不再要求把客户图像塞入 initramfs。
第一次建立该基座时，本批机器统一刷配套新完整 IMG。此后普通动画、Logo、语言字形及播放器更新通过配套完整 UPK 发布；只有早期挂载入口或内核/驱动改变才涉及基座 IMG。
仅刷旧 kernel 而更新 root 不能消除旧内核中的品牌画面，因此不把这种混装称为统一开机。

完整版本与掉电恢复
/etc/un260/boot-active：本次当前版本和上一完整版本，严格 5 行。
/etc/un260/boot-active.previous：独立上一版本选择记录，可用于 active 损坏时恢复。
/usr/local/lib/un260-boot/versions/<ID>：player、theme.pack、manifest，大小、SHA256、权限、ELF 与模式需匹配。
只有整体升级事务已经提交，才持久化发布新的 active；发布前保存上一记录，掉电恢复幂等继续。
/dev/.un260-boot-bundle：本次实际显示版本快照。旧版本清理保留 active、previous 与 live，按已持久化清理计划处理已验证目录。
/dev/.un260-boot-platform：仅由新 PID1 创建的 RAM 基座标识。新的启动包 guard 与旧安装器的严格检查相互约束，阻止已验证旧基座误装；新基座不允许旧普通包静默覆盖新交接协议。

故障和回退
活动版本缺失、SHA 错、ELF/资源异常、首帧失败：尝试上一完整版本；视觉启动仍失败则继续正常 /linuxrc，让应用走原有显示路径。
缺少校准文件、显式关闭提前显示、升级事务恢复中：让现有校准或维护流程拥有显示。
统一升级请求未完成时，PID1 用请求 SHA 与持久化完成回执判断是否延后品牌显示。请求完成后虽仍保留在磁盘，也不会拖慢下次正常开机。
升级恢复成功，或失败但当前应用已验证可启动时，启动服务只终止并回收本次创建的升级画面，再启动当前品牌资源包；未退出则有界等待并阻止两个渲染者并发。当前应用不安全时保留维护画面。
播放器探测暂时无响应或 ABI 不可信：主 UI 等待真实 lease，未拿可信快照前只探测，不发送接管命令，不成为第二个绘制者。
播放器退出：只有真实 lease 释放后才回退应用绘制。显示 FD 保留至主 UI 生命周期结束，避免提前释放。
即便播放器在主 UI 启动前退出，已经确认首帧后写入的 RAM 版本记录也会保留；主 UI 验证这一记录后直接准备自检，不再播放旧品牌动画。尚未成功显示任何首帧时，保留原应用启动回退路径。
主控/输入/配置初始化失败：向播放器请求错误交接，显示原有故障提示，不将 Logo 的出现误判成系统可用。
未知或损坏的语言配置：本次早期 Welcome 回退英文，不改写客户配置；语言切换下一次开机生效于整段欢迎显示。
root 无法挂载：保留系统故障与恢复镜像路径，不格式化、不自动反复重启；此属于底层启动故障，品牌包不能修复。

构建与测试边界
交付结果文件记录本次实际交叉编译、完整 make、包匹配、文件哈希与测试日志。统一固件同时保留此前十语言手写 Welcome，以及用户授权协调的满口恢复修复。
主机 IPC、像素、资源校验、事务故障注入和交叉编译不能证明板上亮屏时间、触摸或真实断电恢复已完成。
历史 root 挂载日志只是 Linux uptime，不是从电源开关开始的光学测量，不能据此承诺固定 3 秒。

板上验收清单
A. 从真实电源按下计时，分别记录：第一幅可见品牌/Logo、Welcome、自检开始、主 UI 可操作；与原 7～8 秒和旧 IMG 约 3 秒分开比较。
B. animation/logo 两种模式；十语言持久化后冷启动；更换客户图片后普通完整 UPK，确认全程使用新品牌且不重播。
C. 正常接主控、触摸未就绪、串口异常和首次校准；确认显示不会抢占维护/校准，错误提示正常。
D. 升级复制、commit、previous 发布、active 发布及 GC 阶段分别断电恢复；确认始终选择完整版本。
E. 人工损坏当前 pack/manifest/active，确认上一完整版本或正常应用回退；错误资源不能被提交。
F. 重复冷启动、服务停止/重启、亮度及扫描页交接，检查白闪/黑闪、残留、触摸和点钞协议。
G. 本次配套 IMG 仅用于已核对的 2K page / 128 KiB erase NAND。历史 4K 镜像不纳入本次交付；其他几何需先完善存储、布局与升级校验，再独立验证。
