## 当前协议规则

- 0x0A 成功开始后，由本轮点钞接管 0x0B；旧目录查询状态不再抢占新明细，也不在跑钞期间自动补发目录查询。
- 16 字节 0x0B，11 字节载荷全 00：开始本轮明细。保留当前币种面额，仅清零各行张数、金额，ADD 开关均采用这套规则。
- 中间行：8 字节十进制面额、3 字节十进制张数。按面额直接覆盖；重复值不重复刷新，减少和零值同样生效。金额按面额乘本行张数精确显示，不借用 0x0E 金额差。
- 载荷全 FF：结束本轮明细。结束帧与停机帧先后不同均能正常进入原 0x0C、0x0D 报告链；不把可选报告接收变成新的 ADD 操作锁。
- UI 不补加上一把，也不补造本轮未发送的面额张数；本轮未收到的既有面额显示零。主控负责发送希望显示的累计结果。
- 0x49 只用于冠字号等原有功能，不再推算 A。0x0E 负责现场总数、总额和停机状态；A 不反写这些总数或重启结束动画。STOP 张数为零时保留最近 LIVE 的既有规则不变。
