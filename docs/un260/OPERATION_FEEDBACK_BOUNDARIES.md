# 操作连续性与提示边界

日期：2026-10-26。来源：用户对叶轮电机调速进入即弹错的反馈。本规范用于后续设计、实现和回归，不代替设备协议。

## 本次问题

进入调速页会自动发送 `0x4B/01` 读取。旧实现把自动读取、手动读取和主动保存的超时都交给同一种全局抬头提示。结果是客户尚未操作，或者已经返回其它设置页，也会收到以 “Impeller motor speed” 为标题的警告。这是提示策略过重，不是客户操作错误。

用户提供的 12:46 日志有两次读取和一次设置 31（`0x1F`），未见任何 `0x4B` 回复。`0x4A` 蜂鸣器回复和伴随的 `0x52` 不属于调速确认。日志只能说明 UI 没有收到可识别的调速回复，不能单独证明主控未发送、设备已拒绝或设置未生效。

## 必须区分的结果

| 场景 | 展示与操作 |
| --- | --- |
| 进入页面触发的自动读取没有成功 | 在所属页面显示未确认或读取失败；不弹全局错误，不影响编辑、返回及其它设置。 |
| 用户主动读取没有成功 | 在所属页面给出可见的读取结果，允许重试；不升级为设备故障或全局锁。 |
| 用户编辑滑条、加减、数字、默认值 | 只更新草稿；除非需求明确要求即时应用，否则不能自动写入设备。 |
| 用户保存且收到匹配成功回复 | 确认设备值并完成保存；附带刷新、日志等失败不能撤销成功。 |
| 用户保存但未收到回复 | 准确提示未收到确认，不能判断是否已生效；保留草稿和最后确认值，释放本次等待，允许正常重试。不能声称成功、明确拒绝或设备已恢复旧值。 |
| 收到明确拒绝回复 | 显示与本次操作对应的真实拒绝；不要混称超时或把无关回复当确认。 |
| 非法参数、真实设备冲突或数据完整性问题 | 只阻止真正冲突的操作；说明证据、影响范围、解除条件和恢复路径。 |

## 实现约束

- 请求所有者负责协议匹配、期限与结束；页面负责草稿和页内反馈。不要靠页面提前短路公共服务的恢复逻辑。
- 自动读取不触发全局抬头警告；页面销毁后不把这类结果弹到其它页面。页内状态随页面生命周期清理。
- 等待只约束同一项不能安全并发的请求，不能扩大到返回、草稿编辑、其它设置、跑钞、历史或全局动画。
- 超时不自动重复写入，不新增协议未要求的握手。主控没有事务号时，不承诺识别所有迟到的同形回复。
- 不通过取消全部校验、假成功、增加永久 busy、单纯延长超时或让客户额外点一次来消除报错。
- 保留正常触摸反馈、动画及刷新；不以减少正常反馈来掩盖接收或状态机问题。

## 验证预期

先按客户行为定义结果，再验证实现：未操作即进入、读取缺失／失败／迟到、只编辑不保存、保存成功／明确拒绝／无确认、同值重试、等待期间返回、退出重进、不同命令穿插。检查提示的对象、次数、位置和恢复步骤；禁止把进入即弹错、永久等待或需要额外操作写成“正确预期”。

代码验证、主机界面验证、交叉构建和实机协议验证分别说明；未收到回复时如实报告证据缺口，不能把责任直接归给主控，也不能忽略 UI 自身的提示问题。
