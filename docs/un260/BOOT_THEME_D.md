# 第四套开机与横向自检（2026-09-15）

## 范围

实现已确认的 Arrival-Flow 设计：浅色背景、手写 Welcome、三次小球动画、横向五项自检、原位 Ready 和进入主界面的短过渡。顶角 U 图标复用第三版 96×96 原图，离线抗锯齿缩小后烘焙到背景；早期程序和 LVGL 使用同一份像素。

普通文本为 Roboto；Welcome 为已离线成形的 Oooh Baby 字形。OFL 随资源交付。不加载系统字体，不在设备上解析 TTF，不进行逐帧解码或文件读写。

## 宏与加速路径

统一入口：`source/artinchip/test-lvgl/un260/lv_core/boot_anim/boot_theme_config.h`。

`UI_BOOT_ANIM_THEME` 默认 `UI_BOOT_ANIM_THEME_D`（4）；A/B/C 为 1/2/3。切换后必须完整 make，生成相匹配的应用及内核 initramfs；不要仅替换应用。前三套入口及自检旧页面保留。

原来的 early-init、根文件系统挂载、显示所有权交接、首帧同步、背光与异步初始化路径保留。第四版使用新的视觉版本标识，拒绝继承旧画面的动画时钟；资源同时嵌入早期程序。没有修改供电时序、CPU 频率或点钞协议。

## 业务与生命周期

- 自检页面仅投影 boot_service 快照，不自行发协议，不凭动画时间推算完成。五项为 Configuration/Sensors/Motor/Electromagnet/Image board。
- 进度按已收到的结果更新；失败行保留失败状态，100% 通知不能覆盖错误。只有全部成功且服务完成才能显示 Ready。
- 原有握手、请求顺序、超时、故障确认进入 Sensor 的行为保留。
- 页面隐藏、退出和销毁会停止自身定时器；重复创建有保护，动画定时器创建失败可以退为静态/原有恢复路径。
- Ready 动画期间暂停隐藏页面预热，静止后继续；从自检成功算起，预热等待上限 4 秒，防止依赖缺失导致卡住。此措施不暂停通信轮询，可能使成功后的静态停留比旧版稍长。
- 主界面使用已有导航和业务初始化，420ms 视觉桥接结束释放资源。没有改写 page_main 布局和日常交互。

## 性能边界

背景和图标离线生成；Welcome 固定位置渐显，避免大字逐帧变形；局部小球与卡片动效使用现有刷新节拍。当前项指示器三轮后静止。真实 LVGL 主机渲染测试确认静止等待阶段无新增脏区/图片解码。

这不代表板上 FPS 已验证。仍需测冷开机、连续开关、主控慢启动、逐项失败/超时、异常按键进入 Sensor、Ready→主界面、点钞时协议吞吐、触摸与内存恢复。若硬件上的透明过渡有压力，下一步应降级过渡而非牺牲正常 UI 性能。
