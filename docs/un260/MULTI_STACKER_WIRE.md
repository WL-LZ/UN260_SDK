# MULTI 接钞口清空通知接入

2026-09-18：用户确认真币口清空通知共 **6 字节**：`FD DF 06 51 01 CRC`。本版替代 ADD 单独测试版；不改普通币种，不提交或刷机。

## 已实现

- 连续 MULTI 点钞保留此前币种摘要，不以 ADD OFF 清空；同币种快照覆盖，不逐把相加。运行总 PCS 沿用各币种快照求和，最终以主控全局 PCS 为准。
- 接收 `0x51`，检查完整帧结构、长度6、字段01，且当前选择MULTI，才执行清空通知。
- 复用历史保存入口，先冻结旧组，再清当前结果和详情缓存；后续计数建立新组。未收到通知时连续两把更新同一历史。
- 历史暂无法接收时返回背压，原帧保留在已有队列前端，不放行后续START，不先清数据。
- 不向主控回发CLEAR，不伪造应答，不修改现有收包/尾字节校验机制。
- 通知晚于START确认或计数活动时记录顺序异常并忽略，避免清除本把数据或堵住结束帧。主控须在下一次START前发送通知。
- 处理函数为命令运行时私有函数，不恢复已经不需要的公共枚举和接口。

## 边界

主控同币种数据须为当前批次累计快照，界面不会自行补加单把数值。通知没有事件序号，不能识别跨批次迟到重发，需主控保证有序发送；空闲连续重复通知仅保持清空结果。未收到通知时不凭总数或起始零帧猜测取钞。
