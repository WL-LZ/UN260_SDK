# Main 渐显计时修复

实机视频显示 Ready 后的渐显分段，最终跳到完整 Main。此前只移除分区动画，没有排除页面初始化占用渐显计时的路径。

## 已确认的代码问题及修复

- 原桥接时间戳在 `ui_manager_switch` 前启动；同步创建/恢复页面若耗时，首次动画回调可能已跨过淡入段乃至结束点。
- 现在维持不透明遮罩，等切页完成后的首次覆盖渲染，再启动完整的 360 ms 文字退场、400 ms 后开始的 600 ms 背景淡出。不把创建与首帧耗时算进渐显。
- 就绪后隐藏页预热优先从实际目标 Main/Pure 开始，再遍历其余页面。原有每次一页、80 ms 间隔、内存准入、4 秒总截止不变。
- 保留居中英文就绪页，不恢复 Main 分区位移，不修改 Main 布局、提前亮屏、协议和面额处理。

这是对已证实计时漏洞的修复；没有板上 PERF 数据，不能把它宣称为视频所有低帧问题的唯一根因或保证已恢复帧率。

## 验证

- 实际 LVGL 测试模拟切页阻塞 1200 ms、首次覆盖帧耗时 180 ms：遮罩保持完整，之后重新计时；700 ms 淡入约一半，1010 ms 清理。
- 四套宏入口、静止零新增重绘、失败保留、Pure/异常退出、定时器失败清理通过。
- Main 优先预热、成功/失败/超时、面额保留回归通过。
- 应用交叉编译、完整 make 成功；162 个载荷内容与权限核对通过。
- 未在实机执行安装，未测实机 FPS，未提交 Git。
