## 源头处理

字体运行时使用编译生成的索引读取 `.bin` 文件，并核对长度与校验值，不读取 `locale_fonts/manifest.json`。该 JSON 是主机构建审计资料，包含字体来源、许可证、覆盖字形及哈希。此前虽压紧为 364,504 字节，仍被装入根分区并在字体变化时重新暂存。

发布流程改为：保留源码完整清单，验证全部字体与清单后，将完整清单保存到构建产物 `images/un260-locale-font-audit.json`，不再放入设备载荷。交付同时保留该文件。字体、程序、库和动画资源不因这一修复改变。

旧设备上的清单通过现有完整静态资源事务退役。安装期间保留旧 inode 和 U 盘备份；启动确认前仍可回退。空间计算不提前抵扣旧文件，也不删除用户历史、配置、照片或未确认回退数据。

单此项减少 360KB 新文件暂存；相同历史升级路径的需求由 10,704KB 降至 10,344KB，原有 2,048KB 余量保持。此为按未压缩字节计算的空间预算，不把 UPK 压缩率或 UBIFS 压缩当作保证。

发布侧预算同时补齐启动确认清单的实际字节数、32KB 元数据开销，以及静态资源退役的备份占用，使其与设备算法一致。设备端容量检查、事务恢复、启动确认与 UI 操作流程不变。

## 后续防止同类问题

- 构建审计、测试样本和离线参考文件保留在主机交付资料中，不随意放入运行时根分区。
- 有跨版本资源变化时，同时比较现场使用的旧基线，核算根分区与应用分区各自的新旧内容共存峰值；只与上一份输出比较不足以覆盖现场跨度。
- 发布工具默认 16MB 资格线不等于每台机器实际可用空间。本次现场 10,488KB 边界必须另有回归证据；设备仍以真实剩余空间判定。
- 不通过缩小余量、删业务数据、提前丢弃回退副本或取消校验掩盖容量不足。未来资源扩大时应重新评估实际容量，有限存储不能作“永远不满”的承诺。
