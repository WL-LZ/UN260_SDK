# UN260 触摸校准与 UI 恢复出厂设置

日期：2026-10-05。适用源码：Linux `/home/pc/d213-100ask/d211`。

## 设置入口和使用

在 Settings → Maintenance → Calibration → Touch calibration 打开。沿用现有设置页的标题、卡片、操作栏、白底与蓝色操作色。

1. 停止点钞，点击 Calibrate。
2. 按顺序触摸五个蓝色十字中心；每点稳定按住至少 80ms，再松手。
3. 完成三个独立位置的 Accuracy check。
4. 验证通过后点击 Save；本地写入和同步成功才应用新矩阵。

每点限时 30 秒，全流程限时 180 秒。多指、抖动、过短/过长按压、输入丢帧、样本不可靠会显示具体原因。验证失败可在同一个位置重试，取消/超时/离开页面不会应用草稿。Save 失败保留当前运行配置，可以直接点击 Save 重试，无需重做已通过的校准。

Use saved calibration 是独立的持久开关。关闭后使用原驱动坐标，但保留已保存矩阵；再次打开无需重新采样。未校准时禁止开启。开关保存失败不提前改变运行状态。页面销毁不取消已接受的写线程，由输入驱动持续轮询收敛；原始手势和点击的整次按压归属保留至所有手指松开。

## 算法和职责

参考成熟 [tslib 项目](https://github.com/libts/tslib)、[ts_calibrate](https://github.com/libts/tslib/blob/master/tests/ts_calibrate.c)、[校准公共流程](https://github.com/libts/tslib/blob/master/tests/ts_calibrate_common.c) 和 [linear 插件](https://github.com/libts/tslib/blob/master/plugins/linear.c) 的五点仿射与独立验证思路。代码独立实现，没有复制上游实现。

- `un260/input/touch_calibration_math`：归一化五点最小二乘仿射拟合、带枢轴消元、矩阵合法性、误差检查与定点映射。
- `un260/app_service/touch_calibration_service`：采样状态、单指按压/松开、时间限制、三个独立验证点、确认矩阵/草稿与写线程。
- `un260/storage/touch_calibration_store`：版本、CRC、设备标识、原始轴范围、显示尺寸、矩阵和 enabled 变量。
- `lv_port_indev`：完整 SYN_REPORT 原始输入接入。质心和各个多指接触点复用同一坐标变换，避免按钮、触摸反馈和手势各用不同坐标。
- `page_37_touch_calibration`：呈现和用户操作，不直接解析输入或写文件。

拟合点误差上限 10 像素，独立验证点误差上限 14 像素；实际触摸精度仍须本机验收。候选矩阵只用于验证，不提前接管按钮位置。最终验证后的新输入正常进入 UI，可以点击顶栏 Save/Back。采样期间保留底部 Cancel 操作带；其余输入优先由采样接管，不触发页面手势。

配置路径是 `/etc/ui_state/touch_calibration.cfg`，临时文件为同目录 `.tmp`。写入采用完整写、文件 fsync、原子 rename 和目录 fsync；全部成功才报告保存并切换运行矩阵。读取必须通过大小、版本、CRC、设备/轴/分辨率匹配和矩阵边界检查，否则回退原驱动坐标并显示原因。普通软件升级保留 `/etc/ui_state`，校准不包含固件版本标识。

若 rename 已完成但目录 fsync 失败，设备此时继续使用旧运行状态，但下次启动可能读到新文件；这类情况只能报告保存未确认，不能承诺掉电后一定恢复旧值。成功 fsync 是软件持久化证据，不能替代真实 NAND、USB、电源与触摸屏试验。现有 RTP/tslib 构建路径明确不启用第二层校准，保持其原有输入滤镜。

## 恢复出厂设置

原页面只向主控发送 0x44、成功后提示重启，并在重启前发送原有 0x3B 清 PRE 请求。本次接入 UI 本地偏好，保留协议确认和延时重启流程。

请求前必须停止计数、诊断、升级与设置事务，等待记录和独立存储工作结束。主控拒绝/超时不清 UI 数据。匹配的成功 ACK 后异步保存本地恢复事务，停止工作模式恢复服务；本地成功后才允许 Restart，本地失败给 Retry local reset，重试只操作本地，不重复发送主控恢复命令。

恢复期间禁止导航、点钞启动、待机及自动升级弹窗，避免旧设置继续写回。事务标记 `factory_reset.pending` 以同目录临时写、文件 fsync、rename 和目录 fsync 建立；只在完整标记持久化后变更设置。标记保留到下次启动，在偏好读取、输入初始化和存储线程启动前重放本地偏好；完成背光初始化和设备树默认亮度持久化后，最后清除标记。主控 ACK 与本地标记建立之间不是跨设备原子事务，用户应等待明确本地成功后重启。存储永久故障或非法事务标记阻止混合配置启动并输出诊断，不能当作成功恢复。

恢复使用各模块已有唯一默认值，不另建一套页面默认值：

| 设置 | 恢复后 |
| --- | --- |
| 故障 Popup 自动提示 / 顶栏 Popup | 开启 / 开启 |
| PURE 点钞 / 灵动岛相关点钞开关 | 关闭 |
| Main 分区、布局、快控顺序 | 默认 A 分区、默认布局、现有默认顺序 |
| 币种卡片、收藏、选中缓存 | 默认视图、无收藏 |
| 设置 PIN / PIN 可见性 | 1111 / 关闭 |
| 截图 / 录像 | 开启 / 关闭 |
| 性能监控 / 性能分析 / 手势 / 触摸反馈 | 关闭 |
| 语言 | English（当前正式发布语言） |
| 亮度 | 背光设备树的出厂默认亮度，按背光服务持久化 |
| 待机超时、布局、轮换 | 1 分钟、首布局、每日轮换 |
| 触摸校准 | 清除矩阵、关闭，使用驱动坐标 |
| 每位操作员的快控 / 自动 QR | 开启 / 关闭 |
| 批次预设 / 点钞配置预设 | 模块既定默认值 |
| 本地工作模式偏好 | 清除缓存，重新建立默认状态 |

保留点钞历史、账本、操作员身份/头像/ID 分配器和导入待机照片。每位操作员的偏好恢复默认，避免删除身份后重用 ID 导致历史归属混淆。原有 PRE 清除仍按协议发送，不把主控清除与 UI 历史文件混为一谈。

早期亮屏可能先读取旧亮度，所以启动续做在原有背光初始化之后显式恢复设备树出厂亮度并持久化，成功后才清除事务标记。普通无恢复事务启动沿用原有行为；背光恢复失败保留标记，不把混合默认值当作恢复成功。

## 构建、升级与验收

交付使用明确版本 `1.0.0-touch-factory-20261005` 的 `UN260_UPDATE.upk`，通过现有 Settings → Data → Upgrade → UI 安装，不需要 img 烧录。正常应用卷直接更新；仍在旧小分区的兼容设备可能按既有统一升级流程提示保留同一 U 盘并重启接续，必须等升级器报告最终完成。实际无法启动 UI/升级入口的异常设备不在此升级路径覆盖范围。

应用重新交叉编译、完整 `make -j4` 和实际 UPK/应用/库/资源一致性核对由交付记录记载。主机测试覆盖算法/退化样本、原始触摸报告、单指/多指/重复帧、保存失败重试、独立开关、配置损坏/设备不匹配/新进程重读、恢复事务中断和启动续做、操作员身份保持、真实 LVGL 页面的操作守卫/显示/生命周期，以及既有主页面和待机回归。

板上验收至少包括：各角/中心准确性、拖动和多指手势、Save 后重启和冷断电再读取、开关保存和升级后保留、主控拒绝/超时不误清除、成功恢复后全部默认状态、记录/操作员身份保持，以及真实恢复事务掉电后的续做。主机测试和编译不代表这些硬件项目已经验证。
