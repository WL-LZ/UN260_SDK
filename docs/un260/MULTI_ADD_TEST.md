# MULTI ADD 判断隔离测试版

> 历史测试记录：现已由 `MULTI_STACKER_WIRE.md` 所述6字节0x51通知接入版替代。下文仅记录当时隔离测试范围。

用户要求先只测试 ADD 判断修复，暂停取钞协议相关开发。

## 保留

- MULTI 开始新一把时，不再以 ADD=OFF 为条件清空旧币种。
- 主控同币种快照仍直接覆盖，不逐帧/逐把累加金额张数。
- 对未更新币种保留已有面额明细；新快照涉及币种重新获取明细。
- 沿用已有 group_generation 历史更新机制，连续两把更新同一条记录。
- 既有手动 CLEAR、切换币种清除行为不变；普通币种流程不变。

## 暂停

取钞事件入口、返回枚举和专用入口测试已移出固件源码，保留在仓库外历史交付目录，没有留下大段注释代码。未增加任何取钞命令解析，也不从总数变化猜测是否取钞。原命令分发文件恢复为 HEAD 原样。

上一版取钞接口原本也未注册到协议分发，所以此次拆除只收敛实现范围，不会声称改变了已经生效的取钞行为。

## 建议上板测试

1. MULTI、ADD OFF：CLEAR 后点 CNY13，不取出，再点 USD15。应看到 CNY13/65、USD15/425，最终总PCS以主控报文28为准，历史一条。
2. 实际取出再点一把，记录从取钞前到第二把结束的完整 RX。此版本不猜测新批次；若主控已有取钞/清除语义，根据报文另行确认解析方案。
3. 手动 CLEAR 后再点，确认当前列表清空、已有历史保留、新结果另建记录。
4. 同币种连续两把核对主控是否提供累计快照；UI仍不加算两把。
5. ADD ON、普通币种、切换币种、详情刷新回归。

主机测试覆盖 MULTI解析、历史分组、重复帧、存储恢复和普通币种能力隔离。完整 make 及升级包一致性检查完成后交付。未刷机、未提交或推送Git。
