# 文本归属与消息分类

本目录管理界面文案，不改变点钞数据、控制协议或存储格式。维护入口和添加语言步骤见 [README](README.md)。

| 类别 | 典型内容 | 接入与责任边界 |
| --- | --- | --- |
| 页面与操作 | Menu、Settings、标题、按钮、空状态、说明、选项 | 页面保存源 key；展示时 `ui_tr`。固定选项用逻辑 ID 触发动作，不能比较译后按钮文字 |
| 通用控件 | 键盘、分页、PIN、显示测试、列表 | 控件默认文案接入词典；传入的用户内容保持原值。`UI_N_` 不执行翻译 |
| 机器状态与处理引导 | 协议对应故障名称、部位、处理步骤、安全提示、自检 | 协议先确定故障枚举和处理动作，UI 再查词典。语言改变不重新报错、不确认故障、不改变步骤或动画状态 |
| 操作进度 | 保存、导入、导出、等待控制器确认 | `UI_NOTICE_PROGRESS`；源 key/参数由服务提供，消息保留独立生命周期 |
| 明确成功 | 控制器接受、保存完成、导出完成 | `UI_NOTICE_SUCCESS`；必须来自真实结果，不能由按钮点击或文案推断 |
| 明确失败 | 拒绝、发送失败、文件错误 | `UI_NOTICE_ERROR`；保留原操作和结果关联 |
| 需处理或结果未确认 | 前置条件不满足、超时、持久化未确认、机器异常摘要 | `UI_NOTICE_WARNING`；不可写成“设置成功”，也不可强行改为已失败 |
| 一般消息 | 操作已取消、用户主动查看提示 | `UI_NOTICE_INFO` |
| 决策框 | 删除、放弃草稿、升级确认等有选择的操作 | 仍使用对话框。显示文字可翻译，按钮 callback 与页面草稿独立于文案 |
| 参数化领域结果 | 文件名、记录数、确认步骤数、金额 | `ui_message_t` 保存模板及复制后的参数；worker 不读全局 UI 语言。只在 UI 展示时格式化 |
| 导出的人类文本 | HTML 报表标题、搜索提示、拒钞说明 | 导出开始时固定 locale；明确的 `data-i18n` 节点和安全 JSON 字典，不对用户数据或整段 HTML/JS 猜测替换 |
| 外部升级状态 | `ui_update.sh` 的可见阶段、失败原因、成功结果 | `tools/gen_update_messages.py` 提取公有消息；`ui_update_message_render` 识别已知模板，数据参数保持原值。状态文件协议不变，未知诊断原样显示 |
| 早期/维护显示 | 原生开机文字、主应用退出后的升级画面 | 独立渲染能力。目前维护字体只支持英语字符，明确使用英语词典；手写 Welcome 资产仍为英语。不能把这两类资产算成已支持新语言 |
| 数据和工程标识 | 冠字号、用户名、票据抬头、文件名、货币代码、协议码、版本、CSV/QR字段、工程日志 | 不作为译文 key，不因语言切换改变。可见解释标题单独翻译 |

通知颜色由上面的 `UI_NOTICE_*` 类型决定，词典只负责文字。不能使用 `failed`、`success` 等英文子串给消息分类。

数值格式、营业日期、票面精度及货币代码继续遵循现有业务规则。本轮不改变小数点、金额计算、冠字号顺序或存储日期。后续地区化格式应建立单独的展示策略，不能改写原始值。

## 检查方式

- `tools/audit_visible_text.py --check --output audit.json` 检查通用显示接口的字面量与源 key 标记，输出来源文件、行号及文案。它是回归防线，不能单独证明动态调用、私有页面包装器或图片没有遗漏。
- `tools/gen_i18n.py --check` 校验词典一致性、格式参数、启用条件、提取遗漏和生成文件哈希；普通增量 make 也执行检查。
- `tools/gen_message_fonts.py --check` 从维护词典与具体消息角色检查现有字号覆盖；消息子集通过不代表全 UI 字库就绪。
- 新语言必须另做完整字形、长文案、方向、输入、报表和板上验证。阿拉伯语与乌尔都语的 RTL、印地语的塑形不能由更换字符串表解决；机器方向示意及原始协议码也不能随 RTL 整体镜像。

当前只发布英语；旧中文/韩文是未启用草稿。所有新增或删除语言都通过 registry 与独立词典维护，不再为每种语言增加一列 C 结构或一组页面条件分支。
