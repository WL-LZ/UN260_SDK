# UN260 图片存储策略（2026-09-07）

不是所有图片都适合编入 C。当前 rootfs 约 54 MiB，全部展开图片编入程序会增加升级时新旧程序共存的峰值空间。

## 日常使用

原图统一放在 `aic_ui/lvgl_data/`，保留原目录和名字。运行：

```sh
python3 tools/convert_lvgl_assets.py
```

完整 SDK `make` 也会通过 CMake 自动执行转换。生成代码位于 `aic_ui/generated_assets/`，不要手改；分类及校验值见其中 `manifest.json`。

- 宽和高都不超过 64 的小图标才考虑嵌入，按路径排序，嵌入预算 256 KiB。分类预算按 4 字节/像素保守计算。
- 有实际透明像素的图标用 ARGB8888（内存 BGRA），完全不透明的图标用 RGB888（内存 BGR）。不可把需要透明的图标强制改为不透明。
- 大背景、卡片及超预算图标保留 PNG/JPEG 等原文件，通过既有解码缓存和快照使用。
- 外部文件要求小写 `.png/.jpg/.jpeg`，大 BMP 等不支持的外部格式会构建报错，需先转 PNG，避免烧录后才出现缺图。
- 页面继续使用原有资源路径；注册表只拦截已嵌入图标，其他路径落回原解码器。新增图片无需逐页注册。
- 图标变大后自动转为外部图片；仅删除旧清单记录且带生成标识的 `.c`，不删除原图。
- 原图继续随完整 UPK 打包。不能随意删除外部大图。

验证命令：`python3 tools/test_assets.py`、`python3 tools/convert_lvgl_assets.py --check`。

此次 115 张图片中 19 张嵌入（65,348 字节），96 张外部使用。颜色/透明度和缓存热身后的实际帧率仍需板端回归，不能只凭程序缩小推断 FPS 提升。
